# Curso de C# completo

Curso práctico de **C# de cero a avanzado**, pensado para quien **recuerda la sintaxis a medias** y sobre todo no recuerda **lo que va arriba de los archivos y cómo se organizan carpetas y proyectos**: por eso empieza justo ahí.

*Verificado: 2026-10-29 con .NET SDK 10.0.113 en Linux. **Todas las lecciones se ejecutaron** y la salida que ves es la real. Lo que no se pudo ejecutar (Unity, WinForms, WPF) se indica.*

## Cómo usar este curso

1. **Escribe cada ejemplo a mano** (no copies y pegues) y ejecútalo. Cambia algo y **predice** qué saldrá antes de ejecutar.
2. Cada lección es **un archivo** que se ejecuta solo, sin crear proyecto (modo «archivo único» de .NET 10):

```bash
dotnet run 03-tipos.cs
```

| Pieza | Significado |
|---|---|
| `dotnet` | La herramienta de línea de comandos de .NET |
| `run` | Compila y ejecuta |
| `03-tipos.cs` | El archivo de C#. Con **un solo archivo** no hace falta `.csproj` |
| `#:property PublishAot=false` | Directiva (primera línea del archivo) que fija una propiedad del proyecto implícito; se usa cuando se necesita JSON por reflexión |

3. Las lecciones **1, 2, 19 y 20** usan **proyectos de verdad**, porque tratan justo de cómo se organizan.
4. Los **comentarios** del código van en español; los nombres, en inglés.
5. Al final de cada lección hay **ejercicios sin solución**: son la parte que fija lo aprendido.

> **Lo más olvidado:** si abres un archivo moderno de C# y **no ves `using` arriba**, no falta nada: están en un archivo generado. La lección 1 lo demuestra.

## Lección 1 · Lo que va arriba del archivo

Es lo que más confunde al volver a C#. Hay **tres cosas distintas** arriba de un archivo:

| Línea | Qué hace | Equivalente en Java |
|---|---|---|
| `using System.Linq;` | **Importa** los tipos de un espacio de nombres para usarlos sin nombre completo | `import java.util.stream.*;` |
| `namespace Tienda.Models;` | **Declara** a qué «carpeta lógica» pertenecen los tipos de este archivo | `package tienda.models;` |
| `global using System.Text;` | Un `using` que vale para **todos** los archivos del proyecto | (no existe) |

### Por qué los proyectos nuevos casi no tienen `using`

Cuando creas un proyecto con `dotnet new console`, el archivo `Program.cs` es **una sola línea** y **no tiene `using`**:


```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>
```

La línea `<ImplicitUsings>enable</ImplicitUsings>` hace que el compilador **genere un archivo** con estos `using` globales (está en `obj/Debug/net10.0/`):


```csharp
// <auto-generated/>
global using System;
global using System.Collections.Generic;
global using System.IO;
global using System.Linq;
global using System.Net.Http;
global using System.Threading;
global using System.Threading.Tasks;
```

Por eso `Console`, `List<T>`, `File` o `Task` funcionan sin escribir nada. Si lo desactivas (`<ImplicitUsings>disable</ImplicitUsings>`), el mismo programa **no compila**:


```text
Program.cs(1,16): error CS0246: The type or namespace name 'List<>' could not be found (are you missing a using directive or an assembly reference?)
Program.cs(2,1): error CS0103: The name 'Console' does not exist in the current context
```

Y se arregla con los tres `using` que faltan:

```csharp
using System;                       // Console
using System.Collections.Generic;   // List<T>
using System.Linq;                  // OrderBy
```

### Un proyecto completo con todas las variantes

Estructura de archivos:


```text
./GlobalUsings.cs
./Legacy/Product.cs
./Models/Product.cs
./Program.cs
./Services/PriceService.cs
./Weird/Thing.cs
```

Los archivos (cada uno con su comentario):


**`Models/Product.cs`**

```csharp
namespace UsingsDemo.Models;   // namespace "de archivo" (C# 10): una línea, vale para TODO el archivo

public record Product(string Name, decimal Price);
```

**`Services/PriceService.cs`**

```csharp
using UsingsDemo.Models;       // los using también pueden ir aquí: cada archivo declara los suyos

namespace UsingsDemo.Services  // namespace "de bloque" (estilo antiguo): hay que abrir y cerrar llaves
{
    public class PriceService
    {
        public decimal WithVat(Product product, decimal vat = 0.21m) => Math.Round(product.Price * (1 + vat), 2);
    }
}
```

**`Weird/Thing.cs`**

```csharp
// La carpeta se llama "Weird" pero el namespace es otro: el compilador NO exige que coincidan.
// Es solo una convención; romperla confunde a todo el mundo.
namespace Totally.Different.Name;

public class Thing { public override string ToString() => "Soy Thing, de otro namespace"; }
```

**`Legacy/Product.cs`**

```csharp
namespace UsingsDemo.Legacy;   // otro "Product" distinto, en otro namespace: por eso existen los namespaces

public class Product { public string Name = "producto antiguo"; }
```

**`GlobalUsings.cs`**

```csharp
// "global using": vale para TODOS los archivos del proyecto. Es lo que hace ImplicitUsings, pero a mano.
global using System.Text;
```

**`Program.cs`**

```csharp
using Totally.Different.Name;              // trae Thing
using UsingsDemo.Models;                   // trae Product (el record)
using UsingsDemo.Services;                 // trae PriceService
using static System.Console;               // using static: usar WriteLine sin escribir "Console."
using Legacy = UsingsDemo.Legacy.Product;  // alias: un nombre corto para un tipo (y evita el choque de nombres)
using Dict = System.Collections.Generic.Dictionary<string, int>;   // alias de un tipo genérico completo

// Console, List, Math, StringBuilder... no necesitan using aquí:
//   - System, System.Linq, System.IO, System.Collections.Generic... vienen de ImplicitUsings (ver obj/.../GlobalUsings.g.cs)
//   - System.Text viene de GlobalUsings.cs
//   - System.Globalization viene de <Using Include="..."/> en el .csproj

var product = new Product("Teclado", 59.90m);                  // Models.Product (el record)
var old = new Legacy();                                        // UsingsDemo.Legacy.Product, gracias al alias
WriteLine($"{product} | {old.Name}");
WriteLine(new PriceService().WithVat(product));
WriteLine(new Thing());

var sb = new StringBuilder("global using");                    // sin "using System.Text;" en este archivo
WriteLine(sb);
WriteLine(CultureInfo.InvariantCulture.Name == "" ? "InvariantCulture (de <Using> en el csproj)" : "otra");
WriteLine(new Dict { ["a"] = 1 }.Count);

// Nombre completo: siempre se puede escribir sin using
WriteLine(System.IO.Path.GetExtension("archivo.cs"));
WriteLine(typeof(Product).Namespace + " | " + typeof(Legacy).Namespace + " | " + typeof(Thing).Namespace);
```

El `.csproj` añade un `using` global **desde el proyecto** (`<Using Include=.../>`):


```xml
<ItemGroup>
  <Using Include="System.Globalization" />
</ItemGroup>
```


Resultado de ejecutarlo:


```text
Product { Name = Teclado, Price = 59.90 } | producto antiguo
72.48
Soy Thing, de otro namespace
global using
InvariantCulture (de <Using> en el csproj)
1
.cs
UsingsDemo.Models | UsingsDemo.Legacy | Totally.Different.Name
```

| Pieza | Significado |
|---|---|
| `using Totally.Different.Name;` | Trae los tipos de ese espacio de nombres |
| `using static System.Console;` | Permite escribir `WriteLine(...)` en vez de `Console.WriteLine(...)` |
| `using Legacy = UsingsDemo.Legacy.Product;` | **Alias**: un nombre corto para un tipo; resuelve choques entre dos `Product` |
| `using Dict = ...Dictionary<string, int>;` | Alias de un tipo genérico |
| `namespace X;` (con `;`) | Espacio de nombres **de archivo** (C# 10): vale para todo el archivo. Es el estilo actual |
| `namespace X { ... }` | Espacio de nombres **de bloque**: estilo antiguo, con llaves |
| `global using` | Vale para todo el proyecto |
| Carpeta ≠ espacio de nombres | `Weird/Thing.cs` declara `Totally.Different.Name`: **compila**. Es solo una convención. Rómpela y confundirás a todos |

### Instrucciones de nivel superior (top-level statements)

Desde C# 9, un programa sencillo **no necesita** `class Program` ni `static void Main`: escribes el código directamente y el compilador crea la clase por ti. Solo **un archivo** del proyecto puede hacerlo, y esas instrucciones deben ir **antes** de las declaraciones de tipos.

```csharp
// Equivale a "static void Main(string[] args)"; "args" está disponible
Console.WriteLine($"Argumentos: {args.Length}");
```

## Lección 2 · Carpetas, proyectos y archivos

Una **solución** agrupa **proyectos**; cada proyecto genera **un ensamblado** (`.dll` o `.exe`). Esta es la estructura típica, creada con estos comandos:

```bash
dotnet new sln -n Tienda
dotnet new classlib -n Tienda.Core -o src/Tienda.Core
dotnet new console  -n Tienda.App  -o src/Tienda.App
dotnet new xunit    -n Tienda.Tests -o tests/Tienda.Tests
dotnet new gitignore
dotnet new globaljson --sdk-version 10.0.113
dotnet new editorconfig
dotnet sln add src/Tienda.Core src/Tienda.App tests/Tienda.Tests
dotnet add src/Tienda.App reference src/Tienda.Core
dotnet add tests/Tienda.Tests reference src/Tienda.Core
```

| Pieza | Significado |
|---|---|
| `dotnet new sln` | Crea la **solución** |
| `-n Tienda` | *Name*: nombre |
| `-o src/Tienda.Core` | *Output*: carpeta donde crear el proyecto |
| `classlib` / `console` / `xunit` | Plantillas: biblioteca de clases / programa / pruebas |
| `dotnet new gitignore` | Crea un `.gitignore` adecuado para .NET |
| `dotnet new globaljson` | Fija qué versión del SDK usa el proyecto |
| `dotnet new editorconfig` | Reglas de estilo para el editor |
| `dotnet sln add ...` | Añade proyectos a la solución |
| `dotnet add A reference B` | El proyecto A **depende** del proyecto B |

El árbol real que resulta (sin `bin/` ni `obj/`):


```text
./.editorconfig
./.gitignore
./Tienda.slnx
./global.json
./src/Tienda.App/Program.cs
./src/Tienda.App/Tienda.App.csproj
./src/Tienda.Core/Class1.cs
./src/Tienda.Core/Tienda.Core.csproj
./tests/Tienda.Tests/Tienda.Tests.csproj
./tests/Tienda.Tests/UnitTest1.cs
```

### Qué es cada archivo

| Archivo / carpeta | Qué es | ¿A Git? |
|---|---|---|
| `Tienda.slnx` (o `.sln`) | **Lista de proyectos** de la solución | Sí |
| `*.csproj` | **Manifiesto del proyecto**: versión de .NET, paquetes, referencias | Sí |
| `Program.cs` | Punto de entrada | Sí |
| `Class1.cs`, `UnitTest1.cs` | Archivos de ejemplo de las plantillas: **bórralos** | — |
| `global.json` | Versión del SDK de **todo** el repositorio | Sí |
| `.editorconfig` | Estilo de código (sangría, nombres) | Sí |
| `.gitignore` | Qué NO se sube | Sí |
| `Directory.Build.props` | (opcional) Propiedades comunes a **todos** los proyectos | Sí |
| `nuget.config` | (opcional) De dónde se descargan los paquetes | Sí |
| `appsettings.json` | Configuración de apps web/servicios | Sí (sin secretos) |
| `Properties/launchSettings.json` | Perfiles de ejecución en desarrollo (puertos) | Sí |
| `wwwroot/` | Archivos estáticos de una web | Sí |
| **`bin/`** | **Resultado de compilar** (`.dll`, `.exe`) | **No** |
| **`obj/`** | Archivos intermedios y generados (incluido el de `using` globales) | **No** |
| `.vs/`, `*.user` | Configuración local de Visual Studio | **No** |

La solución en `Tienda.slnx`:


```xml
<Solution>
  <Folder Name="/src/">
    <Project Path="src/Tienda.App/Tienda.App.csproj" />
    <Project Path="src/Tienda.Core/Tienda.Core.csproj" />
  </Folder>
  <Folder Name="/tests/">
    <Project Path="tests/Tienda.Tests/Tienda.Tests.csproj" />
  </Folder>
</Solution>
```

Un proyecto de pruebas, con sus **paquetes NuGet** y su **referencia** al proyecto que prueba:


```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <IsPackable>false</IsPackable>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="coverlet.collector" Version="6.0.4" />
    <PackageReference Include="Microsoft.NET.Test.Sdk" Version="17.14.1" />
    <PackageReference Include="xunit" Version="2.9.3" />
    <PackageReference Include="xunit.runner.visualstudio" Version="3.1.4" />
  </ItemGroup>

  <ItemGroup>
    <Using Include="Xunit" />
  </ItemGroup>

  <ItemGroup>
    <ProjectReference Include="..\..\src\Tienda.Core\Tienda.Core.csproj" />
  </ItemGroup>

</Project>
```

| Elemento del `.csproj` | Significado |
|---|---|
| `Sdk="Microsoft.NET.Sdk"` | Tipo de proyecto (`.Web` para ASP.NET Core) |
| `TargetFramework` | Versión de .NET (`net10.0`; con `-windows` solo Windows) |
| `ImplicitUsings` | Genera los `using` globales |
| `Nullable` | Activa el análisis de `null` |
| `PackageReference` | Dependencia **NuGet** con versión |
| `ProjectReference` | Dependencia de **otro proyecto** |
| `<Using Include="Xunit" />` | `using` global para el proyecto |

El `global.json`:


```json
{
  "sdk": {
    "version": "10.0.113"
  }
}
```

### Convenciones de nombres y organización

| Qué | Convención |
|---|---|
| Archivo | `PascalCase.cs`, normalmente **un tipo por archivo** |
| Clases, métodos, propiedades | `PascalCase` |
| Interfaces | Prefijo `I`: `ITaskRepository` |
| Variables locales y parámetros | `camelCase` |
| Campos privados | `_camelCase` |
| Carpetas de proyectos | `src/` para código, `tests/` para pruebas |
| Espacio de nombres | **Igual que la carpeta** (convención, no regla del compilador) |

**Regla de dependencias:** el proyecto de **lógica** (`Core`) **no** referencia al de interfaz; la interfaz (consola, ventana, web) **sí** referencia a `Core`. Así la lógica es reutilizable y probable.

## Lección 3 · Tipos y variables

Tipos numéricos, `decimal` frente a `double`, `string`, `var`, conversiones, desbordamiento, valor frente a referencia.

**Archivo:** `03-tipos.cs`  ·  **Ejecutar:** `dotnet run 03-tipos.cs`

```csharp
// Lección 3: tipos y variables
// Ejecutar con: dotnet run 03-tipos.cs

// ---- Tipos numéricos enteros (con y sin signo) ----
int age = 31;                    // 32 bits: de -2 147 483 648 a 2 147 483 647
long population = 8_100_000_000; // 64 bits; los _ separan miles (solo para leer mejor)
byte small = 255;                // 8 bits sin signo: 0 a 255
uint positive = 4_000_000_000;   // 32 bits sin signo

// ---- Decimales: double (rápido, aproximado) y decimal (exacto, para dinero) ----
double ratio = 0.1 + 0.2;
decimal price = 0.1m + 0.2m;     // el sufijo m marca un literal decimal
float tiny = 1.5f;               // el sufijo f marca un float (32 bits)

Console.WriteLine($"double: {ratio}   decimal: {price}");
Console.WriteLine($"¿0.1+0.2 == 0.3?  double: {ratio == 0.3}   decimal: {price == 0.3m}");

// ---- Otros tipos básicos ----
bool active = true;
char letter = 'Ñ';               // un carácter: comillas simples
string name = "Ana";             // texto: comillas dobles
object anything = 42;            // object: cualquier cosa (todo hereda de object)
var inferred = 3.14;             // var: el compilador deduce el tipo (double). Sigue siendo estático.

Console.WriteLine($"{age} {population} {small} {positive} {tiny} {active} {letter} {name} {anything} {inferred}");

// ---- Tipos en el sistema: cada palabra clave es un alias de un tipo de .NET ----
Console.WriteLine($"int es System.{typeof(int).Name}, string es System.{typeof(string).Name}, decimal es System.{typeof(decimal).Name}");

// ---- Rangos y desbordamiento ----
Console.WriteLine($"int.MaxValue = {int.MaxValue}, int.MinValue = {int.MinValue}");
int max = int.MaxValue;
Console.WriteLine($"max + 1 sin comprobar = {unchecked(max + 1)}  (da la vuelta, sin avisar)");
try
{
    Console.WriteLine(checked(max + 1));   // checked: lanza excepción si desborda
}
catch (OverflowException e)
{
    Console.WriteLine($"checked avisa: {e.Message}");
}

// ---- Conversiones ----
int whole = (int)3.99;           // conversión explícita (cast): trunca, no redondea
double widened = age;            // implícita: no se pierde nada
int parsed = int.Parse("42");    // texto -> número; lanza excepción si no es válido
bool ok = int.TryParse("abc", out int result);   // TryParse no lanza: devuelve true/false
string text = 42.ToString();
Console.WriteLine($"{whole} {widened} {parsed} {ok} {result} '{text}' {Convert.ToInt32("7") + 1}");
Console.WriteLine($"{Math.Round(2.5)} {Math.Round(3.5)} {Math.Round(2.5, MidpointRounding.AwayFromZero)}  (redondeo bancario por defecto)");

// ---- Constantes y readonly ----
const double Pi = 3.14159;       // se conoce al compilar y no puede cambiar
Console.WriteLine($"Pi = {Pi}");

// ---- Valores por defecto y tipos que admiten null ----
int? maybeNumber = null;         // int? = "int o nada"
Console.WriteLine($"default(int) = {default(int)}, default(bool) = {default(bool)}, maybeNumber = {maybeNumber?.ToString() ?? "null"}");

// ---- Tipos de valor frente a tipos de referencia ----
int a = 5;
int b = a;           // se COPIA el valor
b = 99;
Console.WriteLine($"valor: a = {a}, b = {b}");

var listA = new List<int> { 1, 2 };
var listB = listA;   // se copia la REFERENCIA: las dos variables apuntan a la misma lista
listB.Add(3);
Console.WriteLine($"referencia: listA tiene {listA.Count} elementos, listB tiene {listB.Count} (son la misma lista)");
```

## Lección 4 · Operadores y control de flujo

Aritmética, lógica, `if`, `switch` (instrucción y expresión), bucles, `break` y `continue`.

**Archivo:** `04-flujo.cs`  ·  **Ejecutar:** `dotnet run 04-flujo.cs`

```csharp
// Lección 4: operadores y control de flujo
int a = 17, b = 5;
Console.WriteLine($"{a} + {b} = {a + b}; {a} - {b} = {a - b}; {a} * {b} = {a * b}");
Console.WriteLine($"{a} / {b} = {a / b} (entero); {a} % {b} = {a % b} (resto); {(double)a / b:F2} (decimal)");

// Incremento y compuestos
int n = 10;
n += 5; n -= 3; n *= 2; n /= 4;   // n = ((10+5)-3)*2/4
Console.WriteLine($"n = {n}; n++ devuelve {n++} y luego n vale {n}; ++n devuelve {++n}");

// Comparación y lógica
Console.WriteLine($"{a > b} {a == b} {a != b} | && {a > 0 && b > 0} || {a < 0 || b > 0} ! {!(a > b)}");
// && y || cortocircuitan: si ya se sabe el resultado, no evalúan el resto
string? text = null;
Console.WriteLine($"cortocircuito: {text != null && text.Length > 3}");   // no falla aunque text sea null

// if / else if / else
int score = 72;
if (score >= 90) Console.WriteLine("A");
else if (score >= 70) Console.WriteLine("B");
else Console.WriteLine("C");

// Operador condicional (ternario)
Console.WriteLine(score >= 50 ? "aprobado" : "suspenso");

// switch clásico (instrucción)
int day = 3;
switch (day)
{
    case 1:
    case 7:
        Console.WriteLine("fin de semana");
        break;                           // sin break no compila: C# no "cae" al siguiente caso
    case >= 2 and <= 6:
        Console.WriteLine("entre semana");
        break;
    default:
        Console.WriteLine("día inválido");
        break;
}

// switch como expresión: devuelve un valor
string DayName(int d) => d switch
{
    1 => "lunes",
    2 => "martes",
    3 => "miércoles",
    >= 4 and <= 5 => "jueves o viernes",
    6 or 7 => "fin de semana",
    _ => "inválido",                      // _ = cualquier otro valor
};
Console.WriteLine($"{DayName(3)} / {DayName(6)} / {DayName(9)}");

// Bucles
for (int i = 1; i <= 3; i++) Console.Write($"for {i}; ");
Console.WriteLine();

int countdown = 3;
```

```csharp
static T Largest<T>(params T[] values) where T : IComparable<T>      // where: restricción
{
    T best = values[0];
    foreach (var v in values) if (v.CompareTo(best) > 0) best = v;
    return best;
}

{
```

```csharp
// Lección 16: delegados, lambdas y eventos
// Un delegado es "un método guardado en una variable". Func, Action y Predicate ya vienen hechos.
Func<int, int, int> add = (a, b) => a + b;             // devuelve algo: la última pieza es el tipo de retorno
Action<string> shout = text => Console.WriteLine(text.ToUpper());   // no devuelve nada

// Captura de variables (closure): la lambda "recuerda" variables de fuera

Action chain = () => Console.Write("uno ");

chain += () => Console.WriteLine("tres");

thermostat.TemperatureChanged += handler;
thermostat.Set(10);
thermostat.TemperatureChanged -= handler;
thermostat.Set(11);

static IEnumerable<int> Apply(IEnumerable<int> source, Func<int, int> transform)
{
    foreach (var item in source) yield return transform(item);
}

{
    public int OldValue { get; } = oldValue;
    public int NewValue { get; } = newValue;
}

        _value = value;
        Console.WriteLine($"Set({value})");
```

## Lección 17 · Asincronía y concurrencia

`async`/`await`, `Task.WhenAll`, cancelación, `lock`, `Interlocked`, canales.

**Archivo:** `17-async.cs`  ·  **Ejecutar:** `dotnet run 17-async.cs`

```csharp
// Lección 17: asincronía y concurrencia
using System.Diagnostics;

// ---- async/await: esperar SIN bloquear el hilo ----
var watch = Stopwatch.StartNew();
string one = await DownloadAsync("a", 300);           // await: "pausa aquí y vuelve cuando termine"
string two = await DownloadAsync("b", 300);
Console.WriteLine($"En SECUENCIA: {one}, {two} -> ~{Round(watch.ElapsedMilliseconds)} ms");

watch.Restart();
Task<string> ta = DownloadAsync("a", 300);            // se lanzan las dos SIN esperar
Task<string> tb = DownloadAsync("b", 300);
string[] both = await Task.WhenAll(ta, tb);           // y se espera a ambas a la vez
Console.WriteLine($"En PARALELO : {string.Join(", ", both)} -> ~{Round(watch.ElapsedMilliseconds)} ms");

// WhenAny: la primera que termine
var fastest = await Task.WhenAny(DownloadAsync("lenta", 400), DownloadAsync("rápida", 100));
Console.WriteLine($"WhenAny: {await fastest}");

// ---- Cancelación ----
using var cts = new CancellationTokenSource(TimeSpan.FromMilliseconds(150));    // se cancela a los 150 ms
try
{
    await LongWorkAsync(cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("Cancelado a tiempo");
}

// ---- Excepciones en tareas: se lanzan al hacer await ----
try { await FailAsync(); }
catch (InvalidOperationException e) { Console.WriteLine($"Capturada tras await: {e.Message}"); }

// ---- Hilos y datos compartidos ----
int unsafeCounter = 0, safeCounter = 0;
var gate = new object();
Parallel.For(0, 100_000, _ =>
{
    unsafeCounter++;                                  // carrera de datos: se pierden incrementos
    lock (gate) { safeCounter++; }                    // lock: solo un hilo a la vez
});
Console.WriteLine($"sin lock: {unsafeCounter} (casi seguro < 100000) | con lock: {safeCounter}");

int atomic = 0;
Parallel.For(0, 100_000, _ => Interlocked.Increment(ref atomic));    // operación atómica, sin lock
Console.WriteLine($"Interlocked: {atomic}");

// ---- Canal productor/consumidor ----
var channel = System.Threading.Channels.Channel.CreateBounded<int>(2);   // cola con capacidad: da contrapresión
var producer = Task.Run(async () =>
{
    for (int i = 1; i <= 5; i++) await channel.Writer.WriteAsync(i);
    channel.Writer.Complete();
});
var consumed = new List<int>();
await foreach (var item in channel.Reader.ReadAllAsync()) consumed.Add(item);
await producer;
Console.WriteLine($"consumidos: {string.Join(",", consumed)}");

// ---- Reglas ----
Console.WriteLine("""
    1. async/await se propaga hacia arriba: un método que espera suele ser async Task.
    2. NUNCA .Result ni .Wait() sobre una tarea: pueden bloquear la aplicación (sobre todo en interfaces).
    3. async void solo para manejadores de eventos; en lo demás, async Task.
    4. Pasa siempre un CancellationToken a las operaciones largas.
    """);

static async Task<string> DownloadAsync(string name, int milliseconds)
{
    await Task.Delay(milliseconds);                   // simula una espera de red (no bloquea el hilo)
    return $"{name} listo";
}

static async Task LongWorkAsync(CancellationToken token)
{
    for (int i = 0; i < 10; i++)
    {
        token.ThrowIfCancellationRequested();         // comprobar si nos han pedido parar
        await Task.Delay(100, token);
    }
}

static async Task FailAsync()
{
    await Task.Delay(10);
    throw new InvalidOperationException("falló la tarea");
}

static long Round(long ms) => (ms + 50) / 100 * 100;  // redondea a centenas para que la salida sea estable
```

## Lección 19 · Pruebas con xUnit

Una **prueba** es código que llama a tu código y comprueba el resultado. Se escribe con el patrón **Arrange - Act - Assert** (preparar, actuar, comprobar). El proyecto de pruebas referencia al proyecto que prueba.

**El código que se prueba** (`src/Shop.Core/Basket.cs`):


```csharp
namespace Shop.Core;

/// <summary>Cesta de la compra: la lógica que queremos probar.</summary>
public class Basket
{
    private readonly List<(string Name, decimal Price, int Quantity)> _lines = [];

    public int Count => _lines.Sum(l => l.Quantity);
    public decimal Total => _lines.Sum(l => l.Price * l.Quantity);

    public void Add(string name, decimal price, int quantity = 1)
    {
        if (string.IsNullOrWhiteSpace(name)) throw new ArgumentException("El nombre es obligatorio", nameof(name));
        if (price < 0) throw new ArgumentOutOfRangeException(nameof(price), "El precio no puede ser negativo");
        if (quantity <= 0) throw new ArgumentOutOfRangeException(nameof(quantity), "La cantidad debe ser positiva");
        _lines.Add((name.Trim(), price, quantity));
    }

    /// <summary>Descuento por tramos: 5 % desde 50 €, 10 % desde 100 €.</summary>
    public decimal TotalWithDiscount() => Total switch
    {
        >= 100m => Math.Round(Total * 0.90m, 2),
        >= 50m => Math.Round(Total * 0.95m, 2),
        _ => Total,
    };
}
```

## Lección 20 · NuGet e inyección de dependencias

**NuGet** es el gestor de paquetes de .NET (el «npm» de .NET). Añadir uno:

```bash
dotnet add package Microsoft.Extensions.DependencyInjection
```

Queda escrito en el `.csproj`:


```xml
    <PackageReference Include="Microsoft.Extensions.DependencyInjection" Version="10.0.14" />
```

La **inyección de dependencias** (DI) es entregar a una clase **desde fuera** lo que necesita, en lugar de que la cree ella. El contenedor lo hace por ti según lo que registraste:


```csharp
using Microsoft.Extensions.DependencyInjection;

// 1) Registrar: decir "cuando alguien pida ISender, entrega EmailSender"
var services = new ServiceCollection();
services.AddSingleton<IClock, SystemClock>();      // una sola instancia para toda la aplicación
services.AddScoped<IRequestLog, RequestLog>();     // una instancia por "ámbito" (en una web, por petición)
services.AddTransient<ISender, EmailSender>();     // una instancia NUEVA cada vez que se pide
services.AddTransient<OrderService>();             // las clases también se registran

// 2) Construir el contenedor
using var provider = services.BuildServiceProvider();

// 3) Pedir: el contenedor crea OrderService y le entrega sus dependencias por el constructor
using (var scope = provider.CreateScope())          // un ámbito = una petición
{
    var first = scope.ServiceProvider.GetRequiredService<OrderService>();
    var second = scope.ServiceProvider.GetRequiredService<OrderService>();
    first.PlaceOrder("Teclado");
    Console.WriteLine($"mismo ámbito, IRequestLog compartido: {ReferenceEquals(first.Log, second.Log)}");
    Console.WriteLine($"mismo ámbito, ISender distinto cada vez: {!ReferenceEquals(first.Sender, second.Sender)}");
    Console.WriteLine($"Singleton compartido: {ReferenceEquals(first.Clock, second.Clock)}");
}
using (var otherScope = provider.CreateScope())
{
    var other = otherScope.ServiceProvider.GetRequiredService<OrderService>();
    Console.WriteLine($"otro ámbito, IRequestLog nuevo: {other.Log.Id}");
}

// 4) Por qué sirve: en las pruebas se entrega un falso sin tocar OrderService
var fake = new OrderService(new SystemClock(), new RequestLog(), new FakeSender());
fake.PlaceOrder("Prueba");

interface IClock { DateTime Now { get; } }
class SystemClock : IClock { public DateTime Now => DateTime.Now; }

interface IRequestLog { int Id { get; } void Add(string line); }
class RequestLog : IRequestLog
{
    private static int _next;
    public int Id { get; } = Interlocked.Increment(ref _next);
    public void Add(string line) => Console.WriteLine($"  [log {Id}] {line}");
}

interface ISender { void Send(string message); }
class EmailSender : ISender { public void Send(string message) => Console.WriteLine($"  [email] {message}"); }
class FakeSender : ISender { public void Send(string message) => Console.WriteLine($"  [falso, no envía nada] {message}"); }

// El constructor declara lo que necesita; el contenedor lo entrega
class OrderService(IClock clock, IRequestLog log, ISender sender)
{
    public IClock Clock => clock;
    public IRequestLog Log => log;
    public ISender Sender => sender;

    public void PlaceOrder(string product)
    {
        log.Add($"pedido de {product}");
        sender.Send($"Pedido de {product} confirmado");
    }
}
```

**Resultado real:**


```text
  [log 1] pedido de Teclado
  [email] Pedido de Teclado confirmado
mismo ámbito, IRequestLog compartido: True
mismo ámbito, ISender distinto cada vez: True
Singleton compartido: True
otro ámbito, IRequestLog nuevo: 2
  [log 3] pedido de Prueba
  [falso, no envía nada] Pedido de Prueba confirmado
```

| Duración | Qué significa |
|---|---|
| `AddSingleton` | **Una** instancia para toda la aplicación |
| `AddScoped` | Una instancia **por ámbito** (en una web, **por petición**) |
| `AddTransient` | Una instancia **nueva cada vez** que se pide |

Por qué importa: en las **pruebas** entregas un falso (`FakeSender`) sin tocar `OrderService`. Es la misma idea que `ITaskRepository` en la API de tareas.

## Lección 21 · De Java a C#

Si vienes de Java, **casi todo lo que sabes sirve**. Esta es la tabla de traducción:

| Idea | Java | C# |
|---|---|---|
| Importar | `import java.util.*;` | `using System.Collections.Generic;` |
| Agrupar tipos | `package x.y;` | `namespace X.Y;` |
| Punto de entrada | `public static void main(String[] args)` | `static void Main(string[] args)` o **instrucciones de nivel superior** |
| Compilar y ejecutar | `javac` + `java` | `dotnet build` + `dotnet run` |
| Proyecto | `pom.xml` (Maven) | `.csproj` |
| Paquetes | Maven Central | NuGet |
| Tipos | `String`, `int`, `Integer` | `string`, `int` (no hay «caja» visible) |
| Getters y setters | métodos `getX()` | **propiedades** `{ get; set; }` |
| Constantes | `final` | `const` (compilación) / `readonly` (ejecución) |
| No heredable | `final class` | `sealed class` |
| Sobrescribir | `@Override` | `override` (**y el método base debe ser `virtual`**) |
| Métodos | virtuales por defecto | **no** virtuales por defecto |
| Interfaces | `IFoo` no es convención | prefijo **`I`** (`IFoo`) |
| Genéricos | **borrado de tipos** | **tipos reales en ejecución** |
| Colecciones | `List`, `Map` | `List<T>`, `Dictionary<K,V>` |
| Consultas | Streams | **LINQ** |
| Datos inmutables | `record` | `record` |
| Nulos | `Optional<T>` | `T?` y análisis de nulos del compilador |
| Excepciones | **comprobadas** y no comprobadas | **solo** no comprobadas |
| Decimal exacto | `BigDecimal` | `decimal` |
| Lambdas | `x -> x * 2` | `x => x * 2` |
| Tareas asíncronas | `CompletableFuture` | `Task` + `async`/`await` |
| Cerrar recursos | `try-with-resources` | `using` |
| Visibilidad por defecto | de paquete | `private` (y existe `internal`) |
| Igualdad de texto | `equals()` (con `==` compara referencias) | `==` **compara el contenido** |
| Enteros sin signo | no hay | `uint`, `ulong`, `byte`… |
| Propiedades calculadas | métodos | `public int Age => ...;` |

**Las cinco diferencias que más tropiezan:**

1. `override` **exige** `virtual` en la base.
2. `==` en `string` compara **contenido**.
3. No hay excepciones comprobadas: nada te obliga a declarar `throws`.
4. Las **propiedades** sustituyen a los getters y setters.
5. **LINQ** y `async`/`await` son parte esencial del día a día.

> **Ejercicio 21.1:** traduce a C# tu programa más reciente de Java y anota las líneas que cambian.
>
> **Ejercicio 21.2:** reescribe un bucle `for` con acumulador de Java usando LINQ.
